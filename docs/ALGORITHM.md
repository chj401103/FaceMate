# 표정 점수 알고리즘 · 기준값 · 검증

FaceMate의 점수는 **감정이나 사회적 능력의 평가가 아니라 "표정 움직임의 연습 달성도"** 입니다.
이 문서는 점수가 어떻게 계산되는지, 기준값(임계값)을 왜 그렇게 잡았는지, 무엇을 어디까지 검증했는지를
**코드 위치와 함께** 정리합니다. 확인하지 못한 것은 확인하지 못했다고 적었습니다.

## 1. 전체 흐름

```
카메라 영상 ─▶ MediaPipe Face Landmarker (브라우저 안에서 실행)
                 ├─ 얼굴 좌표 478개
                 └─ blendshape 52개 (예: mouthSmileLeft, browDownLeft, eyeWideLeft, jawOpen)
        ─▶ ① 얼굴 좌표계로 바꾸기 (얼굴 너비 단위, 머리 기울기·거리 영향 줄이기)
        ─▶ ② 편안한 기본 표정 2초 평균 = 개인 기준선(baseline)
        ─▶ ③ 기준선에서 "조금만 더" 움직인 위치/값 = 개인 목표
        ─▶ ④ 현재 값이 기준선→목표 사이 어디쯤인지 0~100%로 계산
        ─▶ ⑤ 얼굴이 정면·같은 거리일 때만 채점 (게이트), 값은 부드럽게 보정
        ─▶ ⑥ 게이지 · 힌트 · 🟢긍정/🔴부정 표시
```

핵심 아이디어는 **남과 비교하지 않고, 내 편안한 표정을 기준으로 내 변화만 본다**는 것입니다.
그래서 사람마다 다른 얼굴 모양·표정 크기에도 같은 방식으로 동작합니다.

## 3. 기준값·임계값 표

값은 모두 코드의 상수이며, 아래 "근거" 열은 **왜 그렇게 정했는지**와 **어떤 확인을 거쳤는지**를 구분해서 적었습니다.

### 3.1 공통 (`src/smile.js`)

| 상수 | 값 | 의미 | 근거 |
|---|---|---|---|
| `MEASURE_MS` | 2000ms | 기본 표정을 재는 시간 | 순간 표정이 아니라 약 2초 평균을 써서 기준선이 흔들리지 않게 함 (설계) |
| 거리 게이트 | 0.8 ~ 1.25배 | 측정 때 대비 얼굴 너비 비율 | 좌표는 이미 얼굴 너비 기준이라 거리 영향이 작지만, 너무 멀거나 가까우면 오차가 커짐. ±20~25% 안에서만 채점 (설계, 경험적으로 정함) |
| 좌우 회전 게이트 | 0.6 ~ 1.67 | 코끝이 좌·우 얼굴 끝에서 떨어진 거리의 비 | 거의 정면일 때만 채점 (설계, 경험적으로 정함) |
| 상하 고개 게이트 | 0.75 ~ 1.33 | 눈~코 거리의 변화 (`anger.js`, `surprise.js`) | 고개를 숙이거나 들면 세로 지표가 한꺼번에 변하므로 그때는 채점하지 않음 (설계) |
| 평활화 | k = 0.4 | 점수를 이전 값과 섞는 비율 | 게이지가 떨리지 않게 함 (설계) |
| `DONE_THRESHOLD` 등 | 0.9 + `HOLD_MS` 1000ms | 연습 완료 조건 | 한 순간 스친 것이 아니라 90% 이상을 1초 유지해야 완료 (설계) |
| 입 점수 : 눈 점수 | 0.8 : 0.2 | 미소 전체 점수 | 눈웃음은 사람마다 신호가 약해 선택 목표라서 비중을 낮춤 (설계, 시험으로 확인) |

### 3.2 미소 · 눈웃음 (`src/smile.js`)

| 상수 | 값 | 의미 | 근거 |
|---|---|---|---|
| `smileTarget` | 기준 + clamp(0.4 × (1−기준), 0.15, 0.35) | 입꼬리 미소 blendshape의 개인 목표 | **무리하지 않는 작은 변화**: 기본 표정에서 +0.15 ~ +0.35만 올리면 목표. 자동 테스트로 이 범위 확인 |
| `eyeTarget` | 기준 + 0.2 | 눈웃음 지표 목표 | 같은 방식으로 "조금만 더" |
| `EYE_SMILE_WEIGHT` | 2.0 | 눈웃음 변화량에 곱하는 민감도 | **현장 시험으로 조정** (아래 4번 참고) |
| `GEOM_APER_TARGET` | 0.15 | 눈 열림이 15% 줄면 목표 (점 위치 방식) | **임시 목표값.** 코드 주석에 "실제 데이터를 보고 조정해야 한다"고 적어 둠 |
| `GEOM_GAP_TARGET` | 0.12 | 볼-눈꺼풀 간격이 12% 줄면 목표 | 위와 같음 |
| 깜빡임 방어 | 깜빡임이 기준보다 0.4 이상 커지면 눈웃음 0점 | 눈을 감아서 점수를 얻지 못하게 | 설계, 자동 테스트로 확인 |

### 3.3 화남 · 눈썹 (`src/anger.js`)

| 상수 | 값 | 의미 |
|---|---|---|
| `BROW_DROP_TARGET` | 0.12 | 눈썹 앞머리-눈꺼풀 간격이 12% 줄면 목표 |
| `BROW_CONVERGE_TARGET` | 0.06 | 양쪽 눈썹 앞머리 사이가 6% 좁아지면 목표 |
| `BROW_AREA_TARGET` | 0.10 | 눈 앞쪽 영역 면적이 10% 줄면 목표 |
| `GLAB_TARGET` | 0.05 | 미간이 5% 모이면 목표 |
| `MOUTH_DOWN_TARGET` / `MOUTH_FROWN_GAIN` | 0.05 / 0.2 | 입꼬리가 입 너비의 5% 내려감 / `mouthFrown` 0.2 상승 |
| `BROW_BLEND_GAIN` | 0.25 | `browDown` blendshape가 0.25 오르면 목표 |
| `BROW_BLEND_WEIGHT` | 0.7 | 점수 = blendshape 70% + 점 위치 30% |
| `BROW_SCORE_WEIGHT` | 3.0 | 눈썹 점수 민감도 (**시험하며 올려 온 값**, 아래 4번) |

수치가 작은 이유: 이용자가 눈썹을 크게 움직이기 어렵고, 위협적으로 보일 정도로 찡그리게 하고 싶지 않기 때문입니다 (설계 의도).

### 3.4 놀람 · 눈썹 올림 / 눈 크게 / 입 벌림 (`src/surprise.js`)

| 상수 | 값 | 의미 |
|---|---|---|
| `SUR_BROW_UP_TARGET` | 0.10 | 눈썹-눈꺼풀 간격이 10% 늘면 목표 |
| `SUR_EYE_TARGET` | 0.10 | 눈 열림이 10% 커지면 목표 |
| `SUR_MOUTH_TARGET` | 0.15 | 입술 사이 간격이 입 너비의 15% 벌어지면 목표 (입을 "살짝" 벌림) |
| `SUR_BROW_GAIN` / `SUR_EYE_GAIN` / `SUR_JAW_GAIN` | 0.25 / 0.25 / 0.20 | 각 blendshape 목표 상승량 |
| `SUR_BLEND_WEIGHT` | 0.7 | blendshape 70% + 점 위치 30% |
| `SUR_PART_WEIGHT` | 눈썹 0.4 · 눈 0.35 · 입 0.25 | 전체 점수의 부위별 비중 |
| `SURPRISE_SCORE_WEIGHT` / `SUR_EYE_SCORE_WEIGHT` | 1.5 / 1.5 | 민감도 가중치 (임시 설정) |

### 3.5 왜 "blendshape + 점 위치" 두 신호를 섞나

사람마다 MediaPipe의 blendshape 반응이 크게 다릅니다. 눈웃음 시험에서 **한 분은 blendshape가 거의 반응하지 않아 점수가 7%까지만 올랐습니다** (아래 4번).
그래서 한 신호가 약해도 다른 신호로 점수가 오르도록 둘을 함께 씁니다. 미소 눈웃음은 두 점수 중 **큰 값**을 써서, 기존 방식으로 잘 나오던 사람의 점수는 내려가지 않게 했습니다.

## 4. 기준값 조정 기록 (실제 시험, 2026-11-05)

작은 규모의 시험입니다. 시험한 사람은 **개발자 본인과 센터의 다른 강사분 1명**이고, 이용자 대상 시험이 아닙니다.

| 순서 | 관찰 | 조치 |
|---|---|---|
| 1 | 본인 눈웃음 달성도가 **31~35%까지만** 올라감 | 눈웃음 변화량에 **1.5배 가중치** 도입 (`EYE_SMILE_WEIGHT`) |
| 2 | 1.5배에서 자연스러운 눈웃음이 **최고 약 61%** | 같은 움직임에서 **약 80%** 가 나오도록 **2.0배**로 조정 |
| 3 | 다른 강사분은 눈웃음이 **최대 약 7%** | blendshape(`cheekSquint`, `eyeSquint`)가 거의 반응하지 않는 것으로 판단 → **눈꺼풀 간격·볼 간격을 점 위치로 직접 재는 보조 방식** 추가, 두 점수 중 큰 값 사용 |
| 4 | 본인은 점수가 **너무 높게** 나옴 (개인차) | 개인 기준선 대비 값이라 사람마다 체감이 다름을 확인. 위 3번의 "큰 값" 정책으로 낮은 사람만 올림 |
| 5 | 화남은 점수가 낮아 눈썹 점수 가중치를 시험하며 상향 | 1.5 → 1.75 → 1.85 → 2.0 → 2.2 → … → **현재 3.0** |
| 6 | 점이 너무 많으면 정신이 없음 (본인·강사 의견) | 연습 화면의 점을 줄임 (미소: 입꼬리·눈·볼, 화남: 눈썹·눈 앞머리) |
| 7 | 점이 너무 크면 얼굴이 가려짐 | 점 크기를 약 절반으로 줄임 (2026-11-06) |

**이 기록의 한계:** 시험 인원이 2명이고, 3번 이후의 재측정 수치는 이 문서에 남아 있지 않습니다. 기준값이 일반적으로 "적절하다"고 말할 근거는 아직 없고, **두 사람에게서 작동하도록 맞춘 값**이라고 보는 것이 정확합니다.

## 6. 모델 로딩 방식과 예외 처리

- **모델 로딩** (`src/App.jsx` `createLandmarker`): 얼굴 인식 모델과 엔진 파일은 사이트 안(`/mediapipe/`)에 함께 들어 있어 외부 주소 없이 불러옵니다. 사이트 파일을 불러오지 못한 경우에만 예비로 외부 주소(jsdelivr, Google 저장소)를 씁니다. 모델은 처음 한 번만 불러옵니다.
- **얼굴이 인식되지 않을 때:** 기본 표정을 재는 중이면 "얼굴이 인식되지 않아 잠시 멈췄어요"를 보이고 측정 시간을 멈춥니다.
- **거리·고개가 크게 바뀔 때:** 채점을 멈추고 "얼굴을 정면으로 하고, 처음 측정할 때의 거리를 유지해 주세요"를 안내합니다 (게이트).
- **카메라 오류** (`startCamera`): 권한 거부(`NotAllowedError`) → "주소창의 카메라 아이콘에서 허용해 주세요", 카메라 없음(`NotFoundError`) → "연결된 카메라를 찾을 수 없어요", 브라우저 미지원 → 안내문. 오류가 나면 카메라를 끄고 처음 상태로 돌아갑니다.
- **모바일 대응:** `viewport` 설정, 좁은 화면(≤520px)에서 카드를 한 줄로, ≤400px에서 아이콘을 줄입니다. 영상은 `playsInline`과 `facingMode: 'user'`(전면 카메라)로 엽니다. 화면 배치는 직접 확인했지만, **모바일에서 카메라 연습이 끝까지 되는지는 체계적으로 확인하지 못했습니다.**

## 7. 개선 계획

1. 화남·놀람 계산에도 자동 테스트 추가
2. 더 많은 사람(연령·안경·조명)으로 시험하고, 결과를 이 표에 계속 추가
3. 센터 이용자가 쓴 뒤 받은 의견으로 기준값 재조정 ("의견 보내기" 기능 활용)
